# Прокси OpenAI и OpenRouter через финский сервер

Приложение в RU обращается к `api-proxy.internal:18080`. SSH-туннель на RU
доставляет запросы в Nginx на финском сервере, а Nginx устанавливает HTTPS-соединение
с соответствующим провайдером. Между серверами трафик шифруется SSH.

Финский Nginx слушает `127.0.0.1:18080`. Входной порт туннеля на RU привязывается
к адресу шлюза Docker `bridge`, который контейнеры получают через `host-gateway`.
На финском сервере для этой схемы нужен публичный SSH-порт.

API-ключи хранятся в приватном `.env` на RU и передаются провайдерам в заголовке
`Authorization`. Конфигурация Nginx отключает журнал запросов и буферизацию,
сохраняет методы, тело и параметры запроса. Автоматические повторения запросов
отключены, чтобы сетевой сбой не создавал вторую платную генерацию.

Поддерживаются обычные ответы, SSE, получение фонового исследования по ID и его
отмена. Таймаут чтения прокси составляет 35 минут, что покрывает текущий лимит
глубокого исследования в приложении — 30 минут. Для DNS используются
`1.1.1.1` и `9.9.9.9`; их доступность проверяется при установке.

## Ресурсы

Начальная оценка для умеренной нагрузки — 1 vCPU, 1 ГБ RAM и 10–20 ГБ SSD.
2 vCPU, 2 ГБ RAM и 20 ГБ SSD дают запас для ОС, обслуживания и обновлений.
Модели выполняются у провайдеров. После запуска оценку уточняют по памяти,
числу одновременных соединений и сетевому трафику.

## Установка на финском сервере

Перед установкой проверить ОС, свободное место, существующие службы и запросы
к OpenAI и OpenRouter с действующими ключами. Следующие пути рассчитаны на
Ubuntu/Debian с пакетным Nginx и `ca-certificates`.

1. Установить `nginx` и `ca-certificates`. Поместить `nginx.conf` в
   `/etc/nginx/conf.d/researcher-api.conf`. На свежем сервере отключить
   стандартный сайт Nginx, если он занимает публичный порт 80.
2. Выполнить `nginx -t`, перезагрузить конфигурацию и проверить
   `curl --fail http://127.0.0.1:18080/health`.
3. Создать отдельного пользователя `api-proxy` с оболочкой
   `/usr/sbin/nologin` для подключения туннеля.
4. Добавить открытый ключ пользователя туннеля с RU в
   `/home/api-proxy/.ssh/authorized_keys` с ограничениями
   `from="77.91.114.154",restrict,port-forwarding,permitopen="127.0.0.1:18080"`.
   Каталог `.ssh` должен иметь права `0700`, файл — `0600`, владелец — `api-proxy`.
   Проверить, что правила `sshd` разрешают этому пользователю локальный
   TCP forwarding. Закрытый ключ остаётся на RU.

## Установка туннеля на RU

1. Создать системного пользователя `api-proxy-tunnel` и принадлежащий ему
   каталог `/etc/researcher-api-proxy` с правами `0700`.
2. Создать там отдельный SSH-ключ `id_ed25519` без парольной фразы и с правами
   `0600`. Его открытый ключ установить на FI по инструкции выше.
3. Добавить ключ финского SSH-хоста в
   `/etc/researcher-api-proxy/known_hosts` после проверки отпечатка. При проверке
   `151.243.247.208` 2026-11-16 наблюдался ED25519
   `SHA256:kTGY9SdZp6Xof8/SzUFiIiT7EDGZqVvXnfdxzehwZJs`.
4. Скопировать `tunnel.env.example` в
   `/etc/researcher-api-proxy/tunnel.env`. Указать актуальный адрес шлюза,
   который выводит команда ниже, и адрес пользователя SSH на FI.

   ```bash
   docker network inspect bridge --format '{{(index .IPAM.Config 0).Gateway}}'
   ```

5. Установить `api-proxy-tunnel.service` в `/etc/systemd/system/`, выполнить
   `systemctl daemon-reload` и `systemctl enable --now api-proxy-tunnel`.
   Проверить `systemctl status api-proxy-tunnel` и `/health` через адрес шлюза.
   Если на RU настроен входной firewall, проверить доступ к порту 18080
   из сети проекта `r-a`.

## Подключение приложения

Overlay рассчитан на версию приложения с прямым OpenAI Responses API и
независимыми настройками OpenRouter. Первое подключение выполняется вместе
с подготовленной выкладкой этой версии и её миграций, включая `013_search_runs.sql`.

В приватном `.env` должны быть действующие `OPENAI_API_KEY` и
`OPENROUTER_API_KEY`. Старые переопределения ключей `LLM_API_KEY`,
`WEBSEARCH_LLM_API_KEY`, `TRANSLATION_API_KEY` и `FEED_TRANSLATION_API_KEY`
должны ссылаться на соответствующего нового провайдера либо быть удалены,
чтобы работали значения из `settings.py`. `LLM_PROVIDER` должен быть `openai`.
Модели и reasoning задаются в `settings.py` и приватном env.

Добавить `deploy/api-proxy/docker-compose.ru.yml` последним Compose-файлом.
Из корня проекта команда проверки конфигурации выглядит так:

```bash
docker compose -p r-a \
  --env-file .env --env-file .env.monitoring \
  -f docker-compose.yml -f docker-compose.prod.yml \
  -f docker-compose.monitoring.yml \
  -f deploy/api-proxy/docker-compose.ru.yml config --quiet
```

Overlay задаёт адреса прокси для `assistant`, `translator`, `feed` и `websearch`,
включая прежние переопределения `base_url` из `.env`.

Перед переключением проверить через туннель короткий запрос к каждому провайдеру,
потоковый ответ OpenAI, создание и получение фонового ответа, а также отмену.
После переключения проверить чат, обзор, перевод, веб-поиск и исследование.
Для последующих команд обслуживания сохранять все четыре Compose-файла.

`/health` проверяет доступность Nginx через туннель. Доступность провайдеров,
валидность ключей и лимиты проверяются отдельными запросами к API.

## Региональные условия

OpenAI предупреждает о возможной блокировке за использование или предоставление
доступа за пределами поддерживаемых стран. Сетевой маршрут через Финляндию
сам по себе не гарантирует соответствия этим условиям.
[Региональные условия OpenAI](https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories).
