# Короткие обзоры русской ленты

При русском языке интерфейса карточка показывает короткий обзор того, что исследовали
и сделали авторы. При английском языке сохраняется исходная аннотация arXiv. Заголовки,
авторы и названия организаций остаются в оригинале.

## Подготовка и хранение

- Фоновый сервис `feed` или монолитный `api` готовит русские обзоры категории `cs.AI`
  для сортировок `new`, `hot`, `popular`, до 50 статей в каждой.
- Gemma получает заголовок и исходную аннотацию и возвращает 1–2 предложения на русском,
  преимущественно 150–230 символов. Ответы длиннее 280 символов, пустые, обрезанные,
  содержащие ссылки или не содержащие русского текста не публикуются.
- `feed_briefs` хранит обзор, исходную аннотацию, модель и дату. Ключ: `arxiv_id` +
  SHA-256 версии инструкции, заголовка и нормализованного исходного описания.
  Обзор общий для всех пользователей и сортировок; изменение только пробелов не
  вызывает новый запрос. Исходная английская аннотация не изменяется.
- `feed_brief_snapshots` хранит полностью подготовленные русские списки. При ошибке
  модели предыдущая лента остаётся доступна. Уже сохранённые обзоры используются
  при следующей попытке, в том числе после перезапуска приложения.
- PostgreSQL advisory-блокировка разрешает подготовку одному процессу одновременно
  и совместима с PgBouncer transaction pooling. HTTP-запрос пользователя читает
  только готовый снимок и не вызывает модель.
- Проверка свежести снимков выполняется раз в 15 минут. При ошибках повторные попытки
  происходят с растущим интервалом до 15 минут. Исходная лента сохраняет часовой кеш Redis.

## Настройка

Применить миграции `009_feed_translations.sql` и `010_feed_briefs.sql`. Первая сохраняет
ранее созданный кэш полных переводов; короткие обзоры используют отдельные таблицы второй.
Обновить `feed` (или `api`) и frontend. До переключения пользователей дождаться готовых
ответов `GET /feed/trending?lang=ru&sort=new` и `sort=hot` от нового сервиса.

```dotenv
FEED_TRANSLATION_MODEL=google/gemma-4-26b-a4b-it
FEED_TRANSLATION_BASE_URL=https://api.proxyapi.ru/openrouter/v1
FEED_REFRESH_MINUTES=15
```

Ключ задаётся через `FEED_TRANSLATION_API_KEY`; если он отсутствует, используется
`LLM_API_KEY`. Отдельный URL наследует `LLM_BASE_URL`. Для прямого OpenRouter указать
`https://openrouter.ai/api/v1`. Секреты в репозиторий не добавлять.

До появления первого снимка русская лента отвечает `503`, `code=feed_preparing`,
`Retry-After: 5`. Frontend показывает загрузку и повторяет запрос без подстановки
английского текста. При отсутствии ключа уже подготовленные снимки остаются доступны.

## Проверка

```bash
cd backend
FEED_TEST_DATABASE_URL=postgres://postgres:password@127.0.0.1:5432/feed_test?sslmode=disable \
  go test -race ./internal/modules/feed ./internal/modules/translation
```

Интеграционные тесты используют отдельную временную схему тестовой БД. Проверяются
миграция, общий кэш между экземплярами сервиса, английская аннотация без изменений,
отсутствие вызовов модели при чтении, новая версия исходника, сохранение старого снимка
при сбое и взаимное исключение фоновых задач. Провайдер заменён локальным HTTP-сервером.
