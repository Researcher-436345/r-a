# websearch

Внутренний FastAPI-сервис для web-search и deep-research. Он отвечает за вызовы
провайдера, системные промпты, нормализацию потоковых ответов и структурированные
источники.

## API

- `GET /health` — проверка состояния сервиса.
- `POST /v1/search/stream` — внутренний SSE-endpoint веб-поиска.

## Настройка

Общие значения объявлены переменными в корневом `settings.py`;
сервис использует их через `import settings`. Env процесса имеет приоритет. Полное описание и таблица моделей:
[`docs/SETTINGS.md`](../../docs/SETTINGS.md).

- Провайдер — прямой OpenAI Responses API, `https://api.openai.com/v1`.
- `OPENAI_API_KEY` — ключ; `WEBSEARCH_LLM_API_KEY` позволяет задать отдельный ключ поиска.
- `LLM_MODEL` — общая модель; `WEBSEARCH_LLM_MODEL` и `WEBSEARCH_DEEP_LLM_MODEL`
  переопределяют её для конкретного режима. По умолчанию используется `gpt-6.1-terra`, уровень рассуждений — `max`.
- В обоих режимах используется обязательный инструмент `web_search`.
- `WEBSEARCH_DOMAINS` задаёт научные домены; пустая строка снимает ограничение.
- У режимов отдельные параметры `WEBSEARCH_*` и `WEBSEARCH_DEEP_*` для уровня
  рассуждений, числа вызовов инструментов, длины ответа и общего таймаута.
- `INTERNAL_TOKEN` защищает внутренние запросы из Go-сервиса `searchapi`.

Deep research работает в фоновом режиме OpenAI. При обрыве upstream-потока
сервис восстанавливает его по идентификатору ответа и последнему событию,
не создавая новое исследование. Сводки рассуждений передаются как временный
прогресс; внутренние рассуждения не выводятся.

Состояние исследования хранит Go-сервис в `search_runs` (миграция
`013_search_runs.sql`). После перезагрузки страницы интерфейс проверяет
готовность отчёта. Удаление чата останавливает незавершённую задачу.

Локальный запуск из корня репозитория после установки зависимостей:

```bash
PYTHONPATH=. python3 -m uvicorn app.main:app --app-dir services/websearch --env-file .env --host 127.0.0.1 --port 8092
```

Дополнительные внутренние маршруты, защищённые `INTERNAL_TOKEN`:

- `GET /v1/search/responses/{response_id}` — получить состояние и готовый отчёт.
- `DELETE /v1/search/responses/{response_id}` — остановить исследование OpenAI.

## Ссылки в ответах

Каждая найденная статья открывается в ридере приложения, поэтому ссылки
ограничены страницами конкретных статей.

- `is_non_paper_url()` решает только по URL, без сетевых запросов, что страница —
  оглавление, список, поиск, профиль, вход, справка или главная страница:
  корень и `list|archive|catchup|year|search|a|login|help` на arxiv.org,
  хосты `info.|blog.|status.|search.arxiv.org`; корень, `venues`, `venue`,
  `group` на OpenReview; корень, `topic`, `search`, `product`, `author`, `venue`
  на Semantic Scholar; корень, `journal`, `browse` на ScienceDirect и тома
  `/vol/N` любого издателя; годовые страницы NeurIPS; всё на
  `openaccess.thecvf.com` вне `/content*` (меню, программы, дни конференции);
  корень, `events`, `venues`, `volumes` в ACL Anthology; тома PMLR; корень
  любого сайта. Те же классы проверяют `not_a_paper` в
  `backend/internal/modules/catalog/indexpages.go` и
  `frontend/src/features/papers/link-kind.ts` — меняйте списки вместе.
- Такие адреса не попадают ни в события `sources`/`source_progress`, ни в
  дописываемый раздел `## Sources`. Раздел дописывается, только если ответ что-то
  цитирует (`[n]` или URL) и в собственном разделе источников модели нет ни одной
  ссылки на статью, поэтому приветствия остаются без списка источников.
- Текст ответа уходит дельтами. Событие `replace` передаёт окончательный текст,
  где аннотации цитат OpenAI преобразованы в Markdown-ссылки. Именно этот текст
  сохраняет `searchapi`; ссылки на не-статьи фронтенд показывает как внешние.
- Системный промпт требует ссылку на страницу конкретной статьи (arXiv abs или
  DOI), точное оригинальное название в тексте ссылки, arXiv ID только из
  результата поиска для этой статьи (иначе DOI или страница Semantic Scholar) и
  короткий ответ без ссылок на приветствия и разговоры не об исследованиях.
